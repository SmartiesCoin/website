Deep dive

What is “Korsh L3”?

Yespower hashes over a working set of 128 × N × r bytes. The old parameters (N=2048, r=32) produced a ~8 MB dataset — far larger than any CPU core’s private L2 cache, so every hash had to be served from the slower, shared L3 cache or main memory. The new parameters (N=256, r=8) shrink it to ~256 KB, small enough to live right next to the core in L2.

Same algorithm, dramatically better cache behavior — that is the whole trick.

Before N=2048 · r=32
8 MB working set
  • Hashed out of L3 / RAM
  • ~0.32 kH/s per core (Apple Silicon)
  • ~0.16 kH/s per core (AMD EPYC)
→
Korsh L3 N=256 · r=8
256 KB working set
  • Hashed inside L2 cache
  • ~8.0 kH/s per core (Apple Silicon, ~25×)
  • ~4.9 kH/s per core (AMD EPYC, ~31×)

Named after Korsh

The configuration is the one designed and run by the Korsh project — the “L3” in the name refers to the fact that this Yespower profile removes the L3 dependency and fits in L2.

Measured on real code

Benchmarks use the node’s own Yespower consensus code — same source, same build, one thread: ~0.32 → ~8.0 kH/s on Apple Silicon (~25×) and ~0.16 → ~4.9 kH/s on AMD EPYC (~31×).

Why it matters for miners

Small working set means hashrate scales with cores: laptops, office PCs and small desktops become viable mining machines again, with less power and heat per hash.

Tokenomics

Emission economics set by the v0.4.0 fork — unchanged by v0.5.0, which upgrades mining only.

Core Parameters

  • Target block time: 120 seconds
  • Daily emission effect: roughly 50% fewer block rewards per day vs 1-minute blocks
  • Halving interval: 1,000,000 blocks
  • Tail emission floor: halvings stop at 1 SMT per block
  • v0.5.0: does not change emission — it upgrades proof-of-work to “Korsh L3”

No version of SMT resets balances. Economy changes set future reward timing; v0.5.0 changes how the network hashes, not how it pays.

Governance Superblocks

10% of the block subsidy is reserved for community governance. These coins are only created in superblocks when funding proposals are approved by masternode vote. This is not a dev fee.

  • Governance reserve: 10% of every block subsidy
  • Superblock cycle: 21,600 blocks (~30 days with 2-minute blocks)
  • Proposal cost: 5 SMT (anti-spam)
  • No approved proposals? Coins are never created, reducing effective emission

Anyone can submit a funding proposal for development, infrastructure, marketing, or community initiatives. Masternode operators vote to approve or reject it. Approved proposals are paid automatically by the network in the next superblock. No individual or team has control over these funds — it is fully decentralized.

Why Rewards Change Over Time

SMT uses three timing layers:

  • Block clock: 2-minute blocks set the daily emission pace.
  • Halving clock: subsidy continues down toward the 1 SMT tail emission floor.
  • Governance clock: superblocks release community funds only when proposals pass.

This keeps SMT alive long-term while reducing daily inflation pressure.

Mining Economics After Korsh L3

  • Per core: ~25–30× more hashes per second on the same hardware
  • Scaling: hashrate scales almost linearly with thread count (each core hashes from its own L2)
  • Energy: less memory traffic per hash means less power and heat
  • Effect: mining returns to everyday CPUs — laptops, desktops, office PCs

Existing wallets, balances, masternodes, and services remain on the same chain. Everyone simply needs to update before activation.

SMT Architecture

Full-featured blockchain with instant transactions, privacy, governance, and masternode infrastructure.

1. PoW Layer — Yespower “Korsh L3”

CPU-first Yespower mining with the Korsh L3 profile (N=256, r=8): an L2-resident working set that makes mining ~25–30× faster per core on the same hardware.

2. InstantSend + ChainLocks

Transactions locked in 2-3 seconds via LLMQ quorums. ChainLocks prevent 51% attacks and block reorganizations.

3. Masternodes (ProTx)

Deterministic masternodes with BLS signatures, operator/owner separation, and automatic PoSe monitoring. Easy setup with Plug & Play Wizard.

4. Shielded TX + Legacy PrivateSend

Transparent addresses remain supported while shielded transaction tooling, legacy CoinJoin mixing, and optional Tor v3 remain available.

5. On-Chain Governance

Masternode operators vote on budget proposals. Approved proposals are funded automatically via superblock payouts every 21,600 blocks.

6. LLMQ Quorums

Long-Living Masternode Quorums power InstantSend, ChainLocks, and governance. Currently using LLMQ_10_60 and LLMQ_10_75 (rotated).
